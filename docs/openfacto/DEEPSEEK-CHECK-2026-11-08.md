# Проверка разговорной речи и DeepSeek — 8 ноября 2026

Обновление: два оставшихся сбоя исправлены отдельным изменением, исходный набор теперь проходит 40/40. Этот документ сохраняет прежние результаты сравнения моделей. Актуальные проверки и ограничения — в [FAQ-WORDING-FIX-2026-11-08.md](FAQ-WORDING-FIX-2026-11-08.md).

## Текущая настройка

В локальном `.env` выбран `deepseek-v4.1-flash` через `https://api.wikivibe.dev/v1/chat/completions`. Используется предоставленный пользователем ключ группы DeepSeek. `AI_VERIFY_MODEL` пуст: и выбор ответа, и независимая проверка выполняются Flash. `AI_THINKING_MODE=disabled`. Автоматического переключения на GPT нет. Прежняя конфигурация сохранена в игнорируемом Git файле `.env.before-deepseek`.

Название протокола OpenAI-compatible не означает использование модели OpenAI. Список `/v1/models` с новым ключом показал четыре модели DeepSeek; старый ключ имел другой список. Ключи не включены в этот отчёт.

## Что изменено

- Безопасная нормализация разговорных вставок для точного опубликованного FAQ, включая латинские `blya`/`suka` и внутренние частицы `блять`/`blya`. Оригинал вопроса сохраняется для AI; даты, отрицания и условия не удаляются.
- Короткий вопрос о времени без истории и голая тема регистрации получают уточнение.
- PDF ищутся одновременно по смыслу и по полнотекстовым совпадениям с русским стеммингом и ограниченным поиском по префиксам. Слова названия мероприятия не вытесняют редкий термин. Исправленный запрос сохраняет свои лучшие результаты при объединении выдачи.
- SQL повторно проверяет организацию, мероприятие, опубликованную версию и доступ участникам перед выдачей текста. Снятый с публикации PDF исчезает из результатов.
- Если модель скопировала отсутствующую в PDF цитату из истории, разрешена одна корректировка выбора из того же списка источников. После неё действуют обычные проверки цитаты, актуальности и поддержки утверждений. Повторный неверный результат не публикуется.
- Режим thinking и отдельная модель проверки включены в подпись AI-операции и политику кэша. Повтор операции не может незаметно поменять модель или режим.

## Живые прогоны

40 сценариев: 18 вариантов регистрации, 6 дедлайна проекта, 4 бейджа, 4 вопроса по PDF, 4 запроса личных исключений, 2 обрывка без контекста, 1 продолжение разговора и 1 попытка заставить бота подтвердить вход без заявки.

Тест вызывает настоящую активацию по имени «лол», поиск и `runScopedAnswer` в режиме evaluation, без кэша. Он не измеряет доставку сообщения Telegram. Проверяются язык, успешный ответ, ссылки на источники, ключевые значения времени/весов, наличие страницы PDF, сохранение условий и политика личных исключений.

Это последовательные прогоны во время исправлений, а не чистый A/B моделей с полностью неизменным промптом.

| Конфигурация | Пройдено | Медиана AI-запросов в движке | p95 |
|---|---:|---:|---:|
| GPT Luna, контрольный прогон | 39/40 | см. исходный JSON | см. исходный JSON |
| DeepSeek Flash | 38/40 | 3,61 с | 7,10 с |
| DeepSeek Pro | 37/40 | 4,38 с | 7,15 с |
| Pro + Flash для проверки | 36/40 | 5,37 с | 8,47 с |

Исключённые эксперименты: дополнительная генерируемая расшифровка вопроса ухудшила выбор языка; она удалена из рабочего кода. Связка двух моделей оказалась медленнее и не улучшила результат; отдельная модель проверки в текущем `.env` выключена.

Один из трёх непройденных случаев Pro — ответ с опубликованным объяснением, что исключение решает человек, вместо ожидаемого системного outcome handoff. Он не обещал разрешение, но строгий тест передачи модератору считает его ошибкой.

## Скорость настоящего Playground

HTTP → API → RabbitMQ → worker → результат, отдельные холодные вопросы:

- Pro: русский 3,801 с; казахский 3,685 с; повторный русский из кэша 0,229 с. Все три проверки прошли.
- Выбранный Flash: русский 4,126 с; повторный русский из кэша 0,243 с. Казахский вопрос в этом прогоне получил ложный отказ за 2,091 с — это НЕ время успешного ответа и НЕ успешная проверка.

Локальный точный FAQ обходится без оплачиваемой генерации; это время движка, а не полная задержка Telegram. Сетевую доставку и ожидание long polling нужно измерять отдельно.

## Ограничения, которые остаются

Полностью решённой проблему ложных отказов считать нельзя. В тестах остались нестабильные казахские варианты и очень короткое продолжение «а во ск бля» при наличии истории. Замена модели сама по себе их не устранила. Во время параллельного стресс-прогона старый ключ также получал HTTP 429; последовательный прогон отделён от этих технических ошибок.

Тарифы `AI_*_MICROS_PER_1K` — локальные оценки для ограничения бюджета, а не подтверждённый счёт WikiVibe. Фактическая цена зависит от тарифа ключа.

## Артефакты и повторный запуск

- `output/pdf/noisy-final-40.json`: контрольный прогон Luna.
- `output/pdf/noisy-deepseek-flash-40.json`: Flash 38/40.
- `output/pdf/noisy-deepseek-pro-initial-40.json`: Pro 37/40.
- `output/pdf/noisy-deepseek-hybrid-40.json`: связка 36/40.
- `output/pdf/deepseek-pro-playground-http.json`: успешная HTTP-проверка Pro.
- `output/pdf/deepseek-playground-http.json`: HTTP-проверка выбранного Flash, включая непройденный казахский случай.
- `tmp/pdfs/check-noisy-questions.mjs`: повторяемый набор; по умолчанию один последовательный исполнитель, ненулевой код выхода при ошибках.

Для текущего локального стенда с загруженным QADAM:

```powershell
node tmp/pdfs/check-noisy-local.mjs
```

Обёртка использует адреса текущего локального Docker-стенда и сохраняет модель, выбранную в `.env`, вместо контрольной модели Luna из вспомогательного скрипта измерений.
