# Проверка OpenFacto — 7 ноября 2026

Проверено текущее рабочее дерево Windows, включая незакоммиченные изменения.
Исходный код приложения не исправлялся. Это результат локальной проверки,
а не подтверждение работы production или реального Telegram webhook.

## Найденные проблемы

### 1. Production build зависит от NODE_ENV родительского процесса

`apps/mini-app/package.json:8` запускает `vite build`, не закрепляя production
для NODE_ENV. `verify:local` загружает корневой `.env`, где сейчас
`NODE_ENV=development`, и передаёт окружение сборке.

Наблюдение: обычный build даёт JS 444,09 kB (gzip 140,68 kB), а build внутри
`verify:local` — 691,27 kB (gzip 208,77 kB), с предупреждением о размере chunk
и строкой `Download the React DevTools` в финальном JS. Проверка секретов
эту проблему не обнаруживает. Это противоречит строке о независимости
production bundle от NODE_ENV в историческом VERIFICATION.md.

Воспроизведение в PowerShell:

```powershell
$env:NODE_ENV = 'development'
pnpm --filter @openfacto/mini-app build
```

Временный способ получить production-сборку:

```powershell
$env:NODE_ENV = 'production'
pnpm --filter @openfacto/mini-app build
Remove-Item Env:NODE_ENV
```

Нужна фиксация production-режима в команде сборки и проверка отсутствия
отладочного React в результате. Исправление в этом аудите не вносилось.

### 2. FAQ integration test не изолирован от опубликованных FAQ в базе

`apps/worker/test/ingestion-faq.integration.mjs:101` ожидает ровно 32 задания
своей организации. `sweepFaqEmbeddings` выбирает 32 задания из всей базы,
а тест затем отбрасывает задания остальных организаций (строка 72).

Браузерный тест оставляет организацию `Organizer browser QA` с опубликованным
FAQ. После него `verify:local` и отдельный FAQ-тест воспроизводимо падают:
`31 !== 32`. После удаления только этой тестовой организации из отдельной QA-базы
тест и полный `verify:local` проходят. Это подтверждённая проблема изоляции
проверок; такой результат сам по себе не доказывает поломку индексации продукта.

Нужны изолированная база/очистка браузерных fixtures и независимость проверки
FAQ от глобальной очереди. Не очищайте пользовательские данные ради тестов.

### 3. Одна команда не проверяет все сценарии

`pnpm check` не включает Python, SQL/Redis integrations, browser e2e, PDF pipeline
и benchmark. У Mini App обычный `test` завершается успешно без unit tests;
`test:browser` запускается отдельно и пропускается без BROWSER_TEST_*.
Рабочий CI не включает этот browser e2e и полный PDF ingestion test.

## Как проверить самому

### Быстро посмотреть интерфейс

Откройте http://127.0.0.1:55173, пока оставленный demo server работает.
Для следующего запуска в PowerShell:

```powershell
Set-Location C:\Users\Ferumm\projects\OpenFacto
pnpm --filter @openfacto/mini-app dev --host 127.0.0.1 --port 55173 --strictPort
```

1. Откройте «База знаний», добавьте FAQ, сохраните черновик и опубликуйте.
2. В Playground задайте точный вопрос: ожидайте текст FAQ и ссылку на источник.
3. Откройте источник из ответа и проверьте версию.
4. Во вкладке «Обращения» ответьте на пример обращения.
5. Переключите RU/KK/EN, сузьте окно, откройте мобильное меню.

Деморежим хранит примеры в памяти; перезагрузка сбрасывает изменения.
Это проверка интерфейса, а не серверного сохранения или доставки в Telegram.

### Инструменты и быстрая автоматическая проверка

```powershell
Set-Location C:\Users\Ferumm\projects\OpenFacto
node --version
pnpm --version
uv --version
docker info
```

Проект требует Node 24–26, pnpm **12.17.0**, Python 3.12+.
В среде агента pnpm по умолчанию оказался 11.25.0. Проверки выполнены
скачанным native pnpm 12.17.0 без смены глобальных настроек. На этом компьютере
он доступен по следующему пути; добавление действует только в текущем терминале:

```powershell
$qaPnpmDir = "$env:LOCALAPPDATA\npm-cache\_npx\033ca203fe6cec57\node_modules\@pnpm\exe.win32-x64"
if (Test-Path "$qaPnpmDir\pnpm.exe") { $env:PATH = "$qaPnpmDir;$env:PATH" }

```

После подтверждения версии:

```powershell
$env:TURBO_FORCE = 'true'
pnpm check
pnpm python:lint
pnpm python:test
pnpm python:smoke
pnpm python:test:integration
pnpm check:spa
Remove-Item Env:TURBO_FORCE
```

После каждой команды проверяйте отсутствие ошибок и `$LASTEXITCODE` (должен быть 0).
PowerShell по умолчанию может продолжить следующую команду после неуспешной предыдущей.

### Проверка интеграций без конфликта с занятым Redis

Запустите Docker Desktop. Следующие переменные относятся только к локальному
тестовому окружению и текущему окну PowerShell; реальные `.env` не меняются.
Указанные пароли — публичные тестовые значения для loopback-сервисов.

```powershell
$env:COMPOSE_PROJECT_NAME = 'openfacto-qa-20261107'
$env:OPENFACTO_POSTGRES_PORT = '55432'
$env:OPENFACTO_REDIS_PORT = '56379'
$env:OPENFACTO_QDRANT_PORT = '56333'
$env:OPENFACTO_S3_PORT = '59000'
$env:POSTGRES_USER = 'openfacto'
$env:POSTGRES_PASSWORD = 'qa-local-password'
$env:POSTGRES_DB = 'openfacto_qa'
$env:DATABASE_URL = 'postgresql://openfacto:qa-local-password@127.0.0.1:55432/openfacto_qa'
$env:REDIS_URL = 'redis://127.0.0.1:56379/0'
$env:QDRANT_URL = 'http://127.0.0.1:56333'
$env:S3_ENDPOINT = 'http://127.0.0.1:59000'
$env:S3_ACCESS_KEY_ID = 'qa-local-access'
$env:S3_SECRET_ACCESS_KEY = 'qa-local-secret'
$env:S3_BUCKET = 'openfacto-qa'
$env:API_PORT = '53001'
pnpm infra:up
pnpm build
pnpm db:migrate
pnpm test:integration
pnpm test:e2e
pnpm verify:local
```

`verify:local` сам останавливает и поднимает сервисы выбранного Compose-проекта.
Запускайте его только в тестовом окружении. Пока проблема № 2 не исправлена,
используйте базу без посторонних опубликованных FAQ.

Для полного PDF-теста отдельно запустите parser:

```powershell
$env:PDF_WORKER_TOKEN = 'qa-parser-token-only-for-local-tests'
$env:PDF_WORKER_PORT = '58001'
uv run --locked --directory apps/pdf-worker python -m openfacto_pdf
```

В терминале с переменными тестовой инфраструктуры:

```powershell
$env:PDF_WORKER_TOKEN = 'qa-parser-token-only-for-local-tests'
$env:PDF_WORKER_URL = 'http://127.0.0.1:58001'
node --test apps/worker/test/ingestion.integration.mjs
node --test apps/worker/test/ingestion-eval.integration.mjs
```

По завершении: Ctrl+C в терминале parser; `docker compose down` в терминале
с `COMPOSE_PROJECT_NAME=openfacto-qa-20261107`. Команду с `-v` не используйте
для обычной остановки: она удаляет данные.

### Реальный кабинет и Telegram

В обычном браузере без Telegram initData открывается демо. Реальный вход требует
MANAGER_BOT_TOKEN и публичного HTTPS, как описано в RUNBOOK.md. В текущем корневом
окружении MANAGER_BOT_TOKEN не задан. Браузерный e2e использовал отдельный
синтетический токен только в тестовых процессах и настоящую локальную базу.

Для самостоятельного browser e2e запускайте API, worker и Mini App на одном
изолированном стеке, задав одинаковый тестовый MANAGER_BOT_TOKEN для API и
BROWSER_TEST_MANAGER_TOKEN для теста, VITE_API_BASE_URL на API и MINI_APP_ORIGIN
на Mini App. Затем:

```powershell
$env:BROWSER_TEST_URL = 'http://127.0.0.1:55174'
$env:BROWSER_TEST_CHROME = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
pnpm --filter @openfacto/mini-app test:browser
```

Не запускайте browser e2e с реальным Manager Bot на пользовательской базе.
Тест оставляет созданные бизнес-записи — используйте отдельную базу.
